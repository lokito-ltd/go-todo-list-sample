## Why

`go-todo` could only show the sample items built into the executable. A usable
to-do list has to accept new items and remember them between runs, and those
items cannot live in the repository's tracked files, so they need a data file
of their own on the user's machine.

## What

`go-todo add <title...>` adds one incomplete item at the end of the list and
prints it as `[ ] <title>`. Every word after `add` becomes part of the title,
joined by single spaces, so quotes are optional. `add` with no title, or only
spaces, prints the usage and exits 2 without touching the list.

Items are kept in `~/.go-todo/items.json`; `GO_TODO_FILE` names a different
file. Until that file exists the list is the built-in sample items, so
`go-todo list` on a fresh machine shows what it showed before, and the first
`add` saves the samples along with the new item. A file that cannot be read,
parsed or written gives a `go-todo: ...` message and exit 1. The usage message
now has a second line, `go-todo add <title>`.

AC0001 keeps its promise unchanged; only its explanatory prose now describes
the data file.

Out of scope: marking items done, removing or editing items, and locking
between two `go-todo` processes running at once.

## Departures

- Extra spaces inside a single argument are collapsed as well, so
  `add "Pay the  rent"` saves "Pay the rent". The plan said the arguments are
  joined with single spaces; AC0002.2 says the words are separated by single
  spaces, and the code follows the requirement's wording.
- The plan was revised twice during the change, each revision approved
  before it was made (see *How*): `Save` was simplified after the first
  verify failed on coverage, and the command dispatch was rewritten from a
  `switch` to `if` statements after the second failed on mutation testing.

## How

**Data file with built-in seed.** `todo.Load` returns the embedded samples
when the file is missing, so nothing has to be written before the first
`add`. A file under the user's home was chosen over
`~/Library/Application Support`, and an environment variable over a `--file`
flag, which would have needed more argument parsing for little gain.

**Atomic save.** `todo.Save` writes `<path>.tmp` and renames it over the real
file, so a failure mid-write never leaves a half-written list. A unique temp
name per run was rejected: it needs `os.CreateTemp` with separate write and
close steps whose errors no test can trigger, which kept `internal/` below
its 95% coverage minimum. Two processes saving at once are out of scope. The
JSON encoding error is ignored because an `Item` (a string and a bool) always
encodes.

**`if` statements, not `switch`.** Go's coverage profile has no block for
`case` expressions, so Gremlins reported mutants there as not covered,
although planting them by hand showed the tests catch them. This is the open
upstream bug go-gremlins/gremlins#298. `run` uses `if` statements, and
`len(args) >= 2` replaces `> 1` so its boundary mutant changes visible
behaviour. Pinning Gremlins to an unmerged fix and switching mutation tools
were rejected for this change; both are in `FOLLOW-UPS.md`.

**Test isolation.** Every test points `GO_TODO_FILE` at a temporary file, so
no test reads or writes the real list in the home folder.
